### Verified options and decision

Current official [AudioClipTrackItem](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/audiocliptrackitem), [ClipProjectItem](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/clipprojectitem), Media, AudioComponentChain, ComponentParam, and [complete type declarations](https://github.com/adobe/premierepro-types/blob/main/src/premierepro.d.ts) were checked; no documented native Audio Gain accessor was found across these routes. Component values are available but Volume-effect parameters are not native Gain. This is not a universal claim that no supported route can ever exist.

Adobe's [SequenceEditor sample](https://github.com/AdobeDocs/uxp-premiere-pro-samples/blob/main/sample-panels/premiere-api/src/sequenceEditor.ts) demonstrates cloning existing track items with time/track offsets inside the same sequence. This is a plausible property-preserving replacement for media reconstruction, not a proved one: gain across all retained segments, linked-pair behavior, trim/move dependencies, static visual/audio properties, and failure isolation need host proof. No replacement editing mechanism or multi-clip reconstruction was shipped.

Re-export comparison is technically promising on this deterministic fixture: unchanged decoded PCM is exact and -6 dB is distinguishable. Export/file-read latency measured 1.314–1.567s for the two baseline renders, plus decode/comparison, with the existing export lock. A reliable check must compare signed samples **per channel**, sample rate/channel count/duration, not WAV headers or the detector's `decodeWav` output: that decoder intentionally collapses signed multichannel samples to nonnegative RMS magnitude and could miss polarity/channel changes. Exact equality on this controlled PCM case does not prove deterministic output for all processors; nondeterminism would need conservative rejection, not a tolerance that accepts meaningful changes.

Cancellation stops plugin waiting, **not host export work**; timeout/retry must not overlap an uncertain export or begin mutations. Audio may change during render or after comparison. [Project.lockedAccess](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/project) protects state only for a synchronous callback (`() => void`), not an awaited export. Verified event invalidation and an immediate safe mutation boundary still need proof. Audio comparison cannot establish Motion/Opacity/visual-property preservation. Therefore the smallest defensible current path is the **global public safety hold**, not a speculative comparison/preservation framework. No properties/layout are currently approved for public Apply; analysis/review remain supported. Multi-clip expansion stops. Full-workflow Undo remains non-atomic.

### September 27 guarded Apply implementation and live host checks

Commits `da96982`, `4ddad5b`, and `baf3afb` added a narrowly scoped Apply runner. The only supported source is one online, ordinary, linked V1/A1 clip pair from the same media item, with matching timing, unit forward speed, no transitions, captions, extra items, added effects, or keyframed parameters. Additional **empty** tracks are allowed; the Premiere fixture has 3V/3A tracks but only V1/A1 populated. Unsupported or changed source snapshots, changed recipes, missing confirmation, and invalid frame plans fail before candidate creation. The panel shows exact frame-aligned removed and retained durations. Its public Apply button is still gated.

The runner creates a new sequence candidate by GUID, creates retained subclips by project-item ID, then edits only that candidate. It verifies the original snapshot is unchanged and checks every output V/A item's count, track, project-item ID, source-relative in/out, timeline start/end, and total frame duration before naming and opening `— PodCut`. An operation record retains the original/candidate IDs, subclip IDs, stages, and errors. A normal failure reconciles artifacts, labels an identifiable partial sequence `PodCut FAILED <operation-id>`, reopens the original if the candidate was active, and reports failure. Retry always creates a fresh candidate; it never resumes a failed one. No artifacts are deleted and the project is not saved automatically. ## Known host/API constraints

- PodCut requires Premiere Pro 26.5+ for `uxp.host.applicationPath` and UXP Developer Tool 2.2+.
- Stop waiting and timeout stop PodCut's listener/polling only; they do not cancel Premiere's host render.
- [SequenceEditor](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/sequenceeditor) has no documented razor/split action; `createRemoveItemsAction` removes whole selected items, not time intervals. [Sequence.createCloneAction](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/sequence) and [Project.lockedAccess / executeTransaction](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/project) worked in Premiere 26.5, but track-item overwrite cloning handled video and audio separately. `createSetInPointAction` shifted the second item's sequence start; `createMoveAction` restored its timeline position while retaining the new source in-point.
- The exact product blocker is transaction safety, not missing test footage: separate video/audio operations can be undone into a desynchronized state, and a four-action grouped transaction returned failure after partially changing video. No documented rollback guarantee or linked-pair cut primitive was found. Do not equate this successful disposable retained-segment experiment with a safe general Apply feature.
